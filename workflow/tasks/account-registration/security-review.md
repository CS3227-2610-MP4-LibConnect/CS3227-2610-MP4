The persistence adapter re-derives `MEMBER`/`LIBRARIAN`, `ACTIVE`/`INACTIVE`, and `isManager: false`; IDs, timestamp and hash are server-created. Forged manager/status/ID/hash/timestamp inputs return 400. No registration session or cookie is created. Login subsequently denies inactive librarians. Synthetic tests cover these boundaries.

Synthetic duplicate, concurrent, delayed-commit, and failed-commit tests pass. Five direct-source attempts per 15 minutes are reserved before Argon2id work using the shared durable store and an isolated counter kind. `X-Forwarded-For` is ignored.
- **Residual limits:** Tests do not cover a real Firestore emulator, production rules/IAM, or deployed reverse-proxy behavior. Email syntax is not defined clearly enough by the approved spec to establish a rejection oracle; see the review report. The login notice uses client-controlled session storage for display only and is never authorization evidence. Manager activation is outside this task and unverified.

No secrets or private user records were accessed or put in review artifacts. No live Firebase calls, production changes, deployment, or merge occurred.

## T06 / R8 target-selection assessment

- **Local emulator path passes:** Explicit mode, project, and loopback host are required; a local probe runs before Admin construction, and a fresh synthetic credential prevents developer ADC use. Real emulator integration passed for user/key writes, member login/session, inactive librarian denial, and shared counter storage. Missing/non-loopback emulator configuration is rejected. - **High blocking production credential-source flaw:** `server/firestore-target.js` calls `applicationDefault()` after checking only environment variables including `K_SERVICE`. The installed Google auth library looks for a well-known gcloud ADC file before runtime metadata. Consequently, a process with production-looking env vars can select developer ADC. Project env agreement does not verify the credential source or runtime project. This fails R8; production must use a metadata-only deployment identity and verify its project before listening. Add mock-based regression coverage without opening local credential files or calling cloud services.
- **Residual deployment boundary:** No actual production connection, IAM/rules check, or deployment was authorized or performed. The untracked `.env` was not read and must remain outside any commit. T06 changes must be reviewed again after the required fix.

## Corrected T06 security conclusion

The production credential-source finding above is **resolved** in the current uncommitted code. `hasWellKnownAdc()` checks for the well-known gcloud ADC file without opening it, and production rejects both that file and `GOOGLE_APPLICATION_CREDENTIALS` before invoking `applicationDefault()`. `getMetadataProjectId()` queries only the fixed runtime metadata IP, requires the `Metadata-Flavor: Google` response header, and requires the metadata project to equal the explicitly configured production project before Admin SDK initialization. The installed auth library's file credential paths are therefore excluded before its metadata path is used. Three new isolated tests cover synthetic ADC-file presence and missing/mismatched metadata; all 21 target tests passed. The local emulator branch remains separate and passed the full local suite.

No live production credential, token, IAM, rules, or deployment check occurred. The latest opt-in local emulator attempt was blocked by its persisted `429` source counter; a prior real emulator run passed. These are verification follow-ups, not evidence of an authorization bypass. The `.env` file remains unread and untracked. No secret contents were accessed or logged.
