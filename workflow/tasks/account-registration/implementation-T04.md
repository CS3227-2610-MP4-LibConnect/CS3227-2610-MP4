The adapter generates a server UUID and timestamp, derives the account status and manager privilege, reuses login email canonicalization and SHA-256 keying, and hashes the exact password using fresh-salted Argon2id (19,456 KiB, two iterations, parallelism one). It creates the user and email key in one Firestore transaction, resolves after commit, maps duplicate create preconditions to `ALREADY_EXISTS`, and propagates other errors. A Member uses `memberId = userId`; a Librarian stores the supplied validated employee ID, `INACTIVE`, and `isManager = false`. The HTTP handler returns generic `409` or `503` as appropriate.
