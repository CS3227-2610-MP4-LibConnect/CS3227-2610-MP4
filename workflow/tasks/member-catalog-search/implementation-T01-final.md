## Endpoint and validation

`GET /api/member/catalog`, same origin, read only. The browser sends the existing cookie with `credentials: 'same-origin'`; no Firestore browser access. The server must validate the cookie-backed session and re-read the current account on **every** request, then require `ACTIVE` and `MEMBER`, using the approved session contract. It does not accept role, status, manager, ownership, or user ID assertions from the request. Authenticate first, then validate query parameters, then access `books`.

Allowed query keys, each at most once: `q`, `title`, `author`, `publisher`, `category`, `isbn`, `synopsis`, `minYear`, `maxYear`, `pageSize`, `cursor`. Any unknown/duplicate key is 400. Text values are strings with at most 256 Unicode code points before trimming and 100 after JavaScript `trim()`; empty/whitespace-only values mean no filter. The entire request target is capped at 8,192 UTF-8 bytes before parsing. The basic `q` matches title **OR** author. Each populated advanced field and the basic clause combine with AND. A collapsed advanced panel omits its advanced criteria and starts a new traversal; reopening restores its local input values. Search runs on form submission; Clear removes all criteria.

`minYear` and `maxYear`, when supplied nonblank, must match exactly four ASCII digits and represent years 1450–2100 inclusive; either alone is valid, both endpoints are inclusive, and `minYear > maxYear` is 400. The UI validates before requesting. Stored Book years are validated as safe integers but are not rejected merely for lying outside the *query* input range, so an older Book remains reachable in unfiltered/text searches. `pageSize` is an optional decimal ASCII integer 1–100, default 100; the dashboard sends/uses 100. `cursor` is optional and at most 4,096 ASCII base64url characters. Empty cursor is invalid.

Text comparison applies JavaScript `trim().toLowerCase()` to the query and `toLowerCase()` to the stored field, then `includes()` for a contiguous substring. This fixes the same runtime Unicode default lowercase mapping on both sides; it does not promise locale collation or full case folding. ISBN matching as an advanced criterion is case-insensitive substring search, while ISBN **identity validation** below uses exact case-sensitive equality. Filter evaluation is server-side across every scanned document, not only displayed cards.

## Book read parser and output

Query `db.collection('books')`, ascending by Firestore document ID. Project/read only `isbn`, `title`, `author`, `publicationYear`, `publisher`, `category`, and `synopsis` from each document, plus its document ID. A valid Book has `isbn` as a nonempty string with no surrounding whitespace and **`doc.id === isbn`** exactly; `title` and `author` are strings with nonempty content after trimming; `publicationYear` satisfies `Number.isSafeInteger`. `publisher`, `category`, and `synopsis` are optional strings: absence becomes `''`, an empty string is allowed, and a present nonstring invalidates the document. A missing or wrong-typed required field, whitespace-only title/author, ISBN whitespace/ID mismatch, or wrong-typed optional field invalidates the document. Skip invalid documents; do not log their raw values or modify them. No ISBN normalization, migration, deduplication write, or BookCopy/status lookup occurs. Unique immutable document IDs plus exact ISBN equality yield at most one card per valid ISBN in a static ordered traversal.

HTTP 200 response has exactly `{ books, nextCursor, scannedAnyDocument, scannedValidBooks, scanComplete }`. `books` is an array of `{ isbn, title, author, synopsis }` only, in document-ID order; `nextCursor` is string or null; the two `scanned*` booleans describe **this raw chunk**; `scanComplete` is boolean. No user, session, BookCopy, or unpublished fields are returned. The client validates exact field names/types before display. A missing synopsis yields the neutral card text “No synopsis provided”; a long one is line-clamped with a keyboard-operable “Read full synopsis” control that exposes the entire text. Render all Book content as text, never HTML.

## Cursor, scan, and empty-state invariants

Fetch at most `pageSize` **raw** documents per request using document-ID ordering, `startAfter(lastScannedDocumentId)`, and `limit(pageSize)`. Validate each, filter each valid Book, and return matches from that raw chunk. If fewer than `pageSize` raw documents are read, set `scanComplete=true` and `nextCursor=null`; otherwise set `scanComplete=false` and encode the last scanned ID. A full final chunk requires one terminal empty request. The UI shows a clear “Load more books” button whenever a cursor exists, even if the chunk has zero matches; it appends matching cards after each continuation. It must not call an empty chunk a no-match result until traversal completes.

Cursor wire format: unpadded base64url of UTF-8 JSON with **exact keys** `v`, `after`, `filterHash`, and `pageSize`, where `v` is integer 1, `after` is the last scanned document ID, `filterHash` is lowercase hex SHA-256 of `JSON.stringify([q,title,author,publisher,category,isbn,synopsis,minYear,maxYear])` after the above normalization (empty text represented as `''`, omitted years as `null`), and `pageSize` is the validated integer. Reject noncanonical base64url, invalid UTF-8/JSON, extra/missing keys, other version, wrong digest/size, or invalid ID with 400 before Book access. Valid ID is nonempty, at most 1,500 UTF-8 bytes, contains no `/` or NUL, is neither `.` nor `..`, and does not match reserved `__.*__`. The cursor is an untrusted traversal hint, not an authorization token; a forged but syntactically valid position can skip that caller's own results, but cannot bypass member authorization. No signing secret or new configuration is introduced. Normal UI navigation uses only server-returned cursors.

For a static collection, ordered nonoverlapping document-ID intervals visit every raw document exactly once. Every valid match is therefore returned once after following all continuations, including sparse matches near the end. This is a normal-browsing guarantee, not snapshot isolation: additions or edits during traversal may require a fresh search. The client discards old cursors/results and ignores or aborts in-flight responses on new submit, Clear, advanced collapse, dashboard brand reset, route change, or logout.

The client ORs `scannedAnyDocument` and `scannedValidBooks` across all responses in one traversal. At completion with zero matches: **no raw documents** means “No books found” (including a never-created collection); raw documents but **no valid Books** means a generic catalog-data error/retry, never “empty catalog” or “no matches”; at least one valid Book with active criteria means “No matching books.” If valid Books exist and no criteria are active, at least one card is reachable. Invalid documents alongside valid ones are skipped without hiding valid results. These flags let the API sequence distinguish the required states without trusting cursor-carried aggregate counts.

## Errors, budget, and UI security

401 for missing/expired/invalid or inactive session, 403 for a verified non-member, 400 for malformed/unsupported query or cursor, 503 for storage/session-service failure. Error body is only `{ error: { code } }`, with fixed codes `UNAUTHENTICATED`, `FORBIDDEN`, `INVALID_QUERY`, or `CATALOG_UNAVAILABLE`; no Book data or sensitive detail. A 401 hides cards and follows the existing signed-out route behavior. A 403 or malformed success response hides cards and fails closed with an access/error state. A 400 shows a field-associated invalid-input state (or generic invalid query for a bad cursor), without presenting old cards as current. A 503/network failure shows a non-sensitive retry for the same traversal, never an empty/no-match claim. Loading is distinct for initial, submitted search, and later page. Authorization denial is not retried as an ordinary catalog failure.

At the dashboard's `pageSize=100`, an expected maximum of 1,000 raw documents implies at most **100 Book document reads per request, 1,000 Book document reads total, and 11 catalog requests** for a complete traversal (the eleventh is the terminal empty request at exactly 1,000). API callers using smaller allowed page sizes may need more requests; their per-request reads still do not exceed 100 and total Book document reads remain at most 1,000 under the same size assumption. These counts exclude current-account/session reads and billing overhead. The 1,000 ceiling is a human-provided expectation, not an observed/enforced storage limit. If exceeded, continue traversal in bounded chunks without silently dropping matches; total reads/requests exceed the conditional budget and should trigger operational architecture review. No cloud data or instance edition was observed. The local-only exception permits this design and synthetic checks despite the Firestore skill's edition prerequisite; any later external access or new data-model/dependency/rules work requires its own approval.
